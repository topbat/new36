# 阶段 A/B/C 一体化交付设计

## 1. 交付结论

采用“本地优先 PWA + 结构化内容底座 + 显式 AI Provider 契约”的方案。它同时服务响应式 Web、可安装移动端和展馆 Kiosk，共用一份内容、证据、训练和审核状态。未配置模型时只启用可解释的本地检索导览，不把规则匹配冒充生成式 AI。

## 2. 三种方案与选择

1. **完整云原生平台：**数据库、对象存储、模型网关和账号系统一次完成。生产能力最强，但需要云账号、密钥、预算、隐私协议与运维权限，当前无法独立验证。
2. **本地优先可发布版本（采用）：**36 计、24 个训练案例、进度、收藏、报告、审核、课堂和 Kiosk 均在浏览器内运行并离线可用；通过 OpenAPI 与 Provider 契约预留服务端升级。
3. **静态内容站：**交付快，但无法覆盖训练、进度、后台、课堂、App 和展馆验收。

## 3. 内容架构

每计必须包含计名、卷、哲学命题、机制、成立条件、不适用条件、伦理边界、反制、八格漫画、现代迁移、证据引用、相似计和反制计。前三计沿用详细审核样稿；其余内容作为 `editorial_draft`，只引用《三十六计》传本文本，不提升为历史事实。

证据对象独立编号。页面显示 `传本文本 / 史料可考 / 文学演绎 / 传统说法 / 编辑解读 / 现代虚构`，所有关系指向有效计策 ID。24 个训练案例覆盖学生、日常、职场三类，每个案例提供事实、未知信息、三个候选方案、可逆性和四维复盘。

## 4. 产品架构

- **六卷文化馆：**卷级导览、36 计索引、进度和收藏。
- **单计展厅：**八格漫画、五层哲学、条件、边界、反制和来源。
- **图谱与搜索：**按标题、机制、场景搜索；展示相似与反制关系。
- **导览与训练：**本地导览负责检索和澄清；训练只运行审核过的案例。
- **学习中心：**收藏、阅读进度、训练复盘、可导出的学习报告。
- **教师模式：**布置课堂任务、控制答案显示、生成班级用讨论卡。
- **审核后台：**角色权限、版本差异、发布状态、回滚和追加式审计记录。
- **渠道模式：**PWA 安装、离线缓存、Kiosk 闲置复位、扫码续学、语音朗读和减少动态效果。

## 5. 状态与数据流

内容以只读 TypeScript 数据发布；用户数据使用带版本号的 localStorage 仓储。浏览、收藏和训练事件只记录计策 ID、选择 ID 与时间，不保存自由文本或个人身份。教师报告在设备内聚合并导出 JSON/打印稿。

审核后台使用领域服务模拟服务端契约：普通编辑只能创建草稿和提交审核；审校员可以退回；发布者可以发布和回滚；审计日志只追加。后续服务端按 OpenAPI 替换仓储，不改页面数据结构。

## 6. 故障与安全

- 无网络：Service Worker 提供应用壳与内置内容。
- AI 未配置：显示“本地检索导览”，不发送请求。
- Provider 超时或结构错误：展示静态训练分支和可理解原因。
- 高风险输入：停止推演，改为安全、正规程序和可信成年人/负责人求助方向。
- Kiosk 闲置：清除本次浏览痕迹并返回卷馆首页。
- 存储损坏：忽略非法版本，恢复空进度，不覆盖内容底座。

## 7. 验收边界

仓库内可完成项以自动化测试、生产构建和真实浏览器验证为准。真实学生/大众/职场用户测试、应用商店上架、硬件展馆连续运行及机构签约需要外部参与者、账号或设备；本阶段交付招募脚本、测试记录模板、上架清单、Kiosk 手册与合作包，但在真实证据出现前保持 `external_pending`。
